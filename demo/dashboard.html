Key Findings

What Works

  • All platform pods run under restricted-v2 SCC — no custom SCCs needed
  • Airbyte runs as UID 1000 — compatible with OpenShift namespace UID constraints
  • Zero impact on RHOAI components — complete isolation confirmed
  • Low resource footprint: ~205m CPU / ~2.2 GiB for platform pods
  • Helm chart passes lint, has tests, README, and NOTES.txt
  • RunAsNonRoot preflight check passes

Known Issues

  • Namespace requires two-step creation for MCS annotation DOCUMENTED
  • Airbyte V2 uses /api/public/v1/ — internal /api/v1/ returns 404 DOCUMENTED
  • temporalUi requires root — must stay disabled on restricted-v2 DISABLED
  • Container images not based on UBI, missing required labels and /licenses
  • Helm chart missing values.schema.json, kubeVersion, and OpenShift annotations

Blockers

  • Replication pod hardcoded resources HIGH
    Orchestrator ignores REPLICATION_ORCHESTRATOR_CPU_REQUEST env var overrides. Hardcodes 2 CPU / 2Gi per container (4 CPU total). Pods fail to schedule on resource-constrained clusters.

    Workaround: manual pod resource patch via jq

Remediation Roadmap

Airbyte Upstream

  1. Fix replication orchestrator to honor resource env var overrides (REPLICATION_ORCHESTRATOR_CPU_REQUEST et al.)
  2. Rebase container images on UBI9 (registry.access.redhat.com/ubi9)
  3. Add /licenses directory with Apache 2.0 license to all images
  4. Add required OCI labels: name, vendor, version, release, summary, description, maintainer
  5. Add values.schema.json to Helm chart
  6. Set kubeVersion constraint in Chart.yaml
  7. Add charts.openshift.io/name annotation
  8. Submit images to Red Hat Connect for certification

Deployer Configuration

  1. Use two-step namespace creation: oc new-project then annotate UID/GID 1000
  2. Use Public API v1 (/api/public/v1/) — internal /api/v1/ returns 404 in V2
  3. Keep temporalUi disabled (requires root, incompatible with restricted-v2)
  4. For production: use external PostgreSQL and S3-compatible storage instead of bundled MinIO
  5. Enable auth in production (global.auth.enabled: true)
  6. Monitor replication pods for scheduling failures; apply resource patch workaround as needed
